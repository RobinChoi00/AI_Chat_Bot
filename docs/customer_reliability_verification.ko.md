# 고객 상담 신뢰성 개선 및 검증

이 문서는 코드와 로컬 검증의 범위를 기록합니다. 실제 모델 정답률, 운영 고객의
문제 해결률, SMTP 수신함 도착률 또는 직원 응답률을 대신하는 점수표가 아닙니다.

2026-10-26 로컬 검증 결과:

- 백엔드 전체 회귀 테스트 **1,844개 통과**.
- 프런트 단위·상호작용 테스트 **160개 통과**, 타입 검사·운영 빌드 통과.
- 운영 빌드에서 데스크톱·모바일 Chromium **14개 검사 통과**.
- 흐름 검증·6개 스모크 시나리오·29개 결정적 답변 검사·Sales 데이터 검사 통과.
- LLM 평가 44개 사례의 구조 검사 통과. 실제 모델 품질 측정 결과는 아님.
- 린트 오류 없음. 기존 관리자 로그인 전체 페이지 이동에 대한 경고 1건은 유지함.

## 고객 흐름

- 기본 운영 설정에서 기록 동의와 유효한 이메일 저장을 마쳐야 상담을 시작합니다.
  서버가 확인하지 않은 브라우저 저장 상태만으로 상담을 열지 않습니다.
- 세션을 처음 읽는 데 실패하면 오류와 재시도 버튼을 표시하고 상담을 잠급니다.
  재시도가 성공하면 저장된 상태와 실제 고객 대화를 복원합니다.
- 새로고침·이어하기는 저장된 고객 입력과 실제 API 답변을 표시합니다. 내부 노트나
  과거 워크플로 원문을 고객에게 보낸 답변처럼 재구성하지 않습니다.
- 최근 100개 메시지부터 표시하고 이전 메시지는 커서로 나눠 불러옵니다. 완료된
  상담도 같은 세션에서 읽을 수 있으며, 명시적으로 시작을 초기화한 상담은 제외합니다.
- 최초 연락처 이메일을 받았다는 사실만으로 최종 접수를 완료한 것으로 취급하지
  않습니다. 최종 제출 전에는 문제 해결 결과 선택으로 돌아갈 수 있습니다.

## 안전 안내와 답변 방어

영어·한국어·스페인어의 화재·불꽃·연기·감전 보고는 모델 호출 전에 확인해 사용 중단
안내와 담당자 검토로 전환합니다. 연기가 없다는 표현과 실제 불꽃 보고를 구분하고,
한국어 배송·설치 일정의 "연기"는 별도로 처리합니다. 위험 상황을 보고한 고객에게
추가 작동 시험이나 내부 패널 개방을 안내하지 않습니다.

승인·확정 배송·치료 효과에 대한 근거 없는 약속을 다국어 후처리에서 검사합니다.
검증된 도구 결과와 조건 설명은 보존합니다. 이 검사는 방어 장치이며, 모든 가능한
언어 표현이나 모든 모델 오답이 제거됐다는 보장은 아닙니다.

## 알림과 장애 복구

증빙·연락처 접수, 상담원 요청, 진행 저장 이메일은 원본 기록과 함께 참조 형태의
알림 작업을 저장합니다. 작업 큐에 이메일 본문·첨부 파일·인증 값을 다시 복사하지
않습니다. 재시작 후에는 저장된 작업을 읽어 처리하며, 실패 시 재시도하고 한도를
넘으면 운영자가 확인할 수 있는 상태로 남깁니다.

상담원 요청은 해당 부서의 지원 메일로 제출하며, 서버가 전송을 확인하기 전에는
전송 성공을 표시하지 않습니다. 메일 제출은 직원 확인이나 콜백 예약을 뜻하지 않습니다.
완료된 동일 요청은 반복 제출하지 않되, 일반 지원 요청 뒤 새로 보고한 안전 문제는
별도의 알림으로 처리합니다.

만료된 처리 권한을 다른 워커가 재확보한 후에는 이전 워커의 늦은 결과가 최신 결과를
덮어쓰지 못하도록 확인합니다. 전화 콜백의 주기적 복구 목록에도 오래된 처리 중
이벤트를 포함합니다.

이메일은 검증된 TLS와 유한한 소켓 대기 시간을 사용합니다. SMTP 수락 직후 서버가
중단되면 실제 전송 여부가 불확실할 수 있으므로 재시도에 따른 중복 가능성은 남습니다.
정확히 한 번 전달된다고 안내하지 않습니다.

## 개인정보와 반복 요청

애플리케이션·Uvicorn 로그에서 상담 재개 토큰, 세션·티켓 경로 값, 민감한 쿼리 값과
이메일을 가립니다. 고객 메시지 원문을 진단 로그로 출력하지 않습니다. 외부 프록시
로그는 운영 설정에서 같은 기준을 적용해야 합니다.

진행 저장 이메일은 IP·세션·수신자별 제한과 짧은 재요청 대기 시간을 사용합니다.
검사와 예약은 SQLite 쓰기 트랜잭션 안에서 처리하므로 동시에 들어온 요청이나
서버 재시작으로 제한을 건너뛰지 못하게 합니다. 제한 시 429와 재시도 시간을 반환합니다.
이전 알림 API도 실제 상담·저장된 연락처를 확인하며 클라이언트가 만든 가짜 대화
기록을 전송하지 않습니다.

## 실행 가능한 검증

백엔드 전체 회귀 검사는 `pytest -q`로 실행합니다. 새 검사에는 모델 호출을 금지한
실제 안전 안내 API, 대화 기록의 권한·페이지 조회, 제출과 작업의 동시 롤백,
처리 중 중단 복구, 오래된 워커의 결과 거부, 반복·동시 발송 제한,
로그 내 토큰·개인정보 제거와 관리자 재시도 인증이 포함됩니다.

프런트 기본 검증:

```bash
cd frontend
npm test
npm run typecheck
npm run lint
npm run build
E2E_USE_PRODUCTION=1 npm run test:e2e
```

Playwright는 실제 Chromium의 데스크톱·모바일 화면에서 React·DOM·폼·저장소·새로고침을
검사합니다. 외부 API 응답은 합성 데이터로 제어합니다. 검사 범위는 이메일 필수 입력,
저장 실패 재시도, 세션 읽기 실패 후 복구, 대화 복원과 이전 페이지 조회, 완료 상담의
읽기 전용 표시, 배송 조회 오류 시 오래된 결과 숨김, 첨부 없는 접수입니다.
브라우저 JavaScript 예외와 hydration 오류도 실패로 처리합니다.

실제 외부 모델·매장 주문·직원 응답·운영 복원 훈련은 별도의 운영 검증이 필요합니다.
`evaluate_llm_quality.py --dry-run`의 사례 구조 검사 결과를 실제 모델 정답률로
해석하지 않습니다. 운영 검증은 [운영 절차](production_runbook.md)와
[고객 성과 측정 문서](measured_customer_success.ko.md)를 따릅니다.
