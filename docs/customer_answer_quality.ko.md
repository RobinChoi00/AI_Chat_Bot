**고객 답변 품질 개선과 Delivery 조회 운영 안내**

이번 개선의 기준은 관리자 기록에서 확인한 질문 오분류, 반복 질문, 제품 조건 누락,
과거 상담의 처리 문구 혼입입니다. 테스트 통과를 실제 고객 해결률이나 완벽한 답변의
증거로 해석하지 않습니다. 실제 결과는 고객의 해결 확인·재문의·상담원 요청 처리와
함께 관찰해야 합니다.

**Sales 상담**

제품 기능·부품·기존 주문·결제 정책 문의는 추천 인터뷰와 구분합니다. 고객이 직접
말한 예산 상한·키·몸무게·메커니즘·문 폭은 대화 상태에 남기고 수정한 값으로 갱신합니다.
추천 후보는 공개된 스펙과 확인 가능한 가격으로 다시 검증하며, 정보가 없는 적합성은
확인됐다고 표현하지 않습니다. 제품명이 애매하거나 다른 모델일 가능성이 있으면
확인 질문을 합니다. 반복되는 불명확한 답변에는 상담원 연결 선택지를 제공합니다.

**Warranty 상담과 상담원 요청**

과거 Freshdesk 상담 원문은 내부 참고 자료로 유지하되 검토 없이 고객용 해결 단계로
사용하지 않습니다. 모델별 공개 자료와 승인된 지식을 사용하고, 티켓 종료·부품 배송·
무료 처리 같은 다른 상담의 결과 문구를 해결 안내에서 제외합니다. 과열 안내와 이미
수행한 점검, 모델별 진단 버튼·가이드의 적용 여부도 구분합니다.

고객이 과열·연기·전기 이상·사용 중 통증 같은 위험을 알리면 진단을 멈추고 사용 중단과
안전한 경우에만 전원 차단을 안내합니다. 위험이 있는 상태에서 재시험을 요구하지 않으며
보증팀 검토 대상으로 저장합니다.

고객이 사람 또는 콜백을 요청하면 현재 진단 질문보다 먼저 처리합니다. 요청과 대화
맥락은 `Awaiting Review` 상태의 관리자 큐에 남습니다. 고객에게는 요청 저장 상태와
직접 연락할 수 있는 번호를 표시합니다. 이 동작 자체가 직원에게 알림을 보내거나
콜백 시간을 예약했다는 뜻은 아닙니다. 담당자는 관리자 큐에서 요청을 확인하고
기존 업무 절차에 따라 대응해야 합니다.
배송 상태 문의의 연락처는 Sales, 제품 위험·보증 문의의 연락처는 Warranty로 표시합니다.

**Delivery 최신 배송 조회**

고객은 Delivery에서 주문번호와 주문 시 사용한 이메일을 입력합니다. 두 값이 같은
매장의 주문과 일치해야 조회 결과를 표시합니다. 모델명은 배송 조회의 필수 항목이
아닙니다. 이메일만으로 다른 주문을 찾아 보여주거나, 잘못된 주문번호를 무시하고
최근 주문을 대신 보여주지 않습니다.

조회는 기존 Shopify·배송사 연결을 사용합니다. 상태·배송사·배송 예정 정보·안전한
추적 링크와 조회 시각을 표시하고, `Refresh`는 새 조회를 요청합니다. 배송사 스캔은
늦게 반영될 수 있으며 조회 시각이 배송사의 마지막 스캔 시각을 뜻하지는 않습니다.
예정일은 배송사가 제공한 예상 정보이고 보장 날짜가 아닙니다. 연결 장애나 주문 확인
실패 시 이전 결과를 새 결과처럼 표시하지 않습니다. 조회만으로 이메일 발송이나
마케팅 등록이 발생하지 않습니다.

공개 API는 다음 세션 경로를 사용하며 기존 개인정보 동의 절차를 따릅니다.

```text
POST /api/v1/warranty/session/{session_id}/delivery-tracking
  order_number, email, domain

POST /api/v1/warranty/session/{session_id}/handoff
  message, domain
```

운영 서버의 매장별 Shopify 자격 증명과 선택적 배송사 연결이 실제 조회 가능 범위를
결정합니다. 연결이 없거나 공급자가 실패하면 조회 불가를 안내하며 배송 상태를
추정하지 않습니다. 외부 연결의 실제 성공 여부는 유효한 주문으로 별도 확인합니다.

**관리자 대화 이력의 출처**

새 Warranty 응답은 `warranty_conversation_messages`에 입력과 최종 고객용 API 답변을
별도로 저장합니다. 이 저장은 개인정보 기록 동의가 있는 세션에서만 수행하며,
관리자 조회·페이지 새로고침·동의/연락처 폼·파일 업로드는 대화로 추가하지 않습니다.
Delivery 조회 폼의 이메일과 주문번호도 대화 메시지에 복사하지 않습니다.

`/admin/history`의 기본 Warranty 대화는 새 응답 기록이 있으면 해당 기록을 표시합니다.
`Workflow reference`에서 이전 질문·답변·보충 기록을 별도로 볼 수 있습니다. 새 기록이
없는 과거 상담은 재구성된 이력으로 표시합니다. 새 기록의 시작 시각을 함께 표시하므로
과거 고객용 답변 전체가 새 방식으로 복구된 것으로 해석하지 않습니다. API 응답 기록은
브라우저 화면에 실제 표시됐거나 고객이 읽었다는 수신 확인과는 구분합니다.

새 테이블은 기존 SQLite에 추가되며 기존 기록을 삭제하지 않습니다. 운영 배포는
기존 백업·정확한 커밋 배포·준비 상태 검사·실패 시 코드 롤백 절차를 사용합니다.
코드 롤백 시 추가 테이블은 남아 있으며 이전 버전이 이를 사용하지 않습니다.

**검증과 이후 개선**

이번 실제 실패 유형을 개인정보 없는 회귀 사례로 유지합니다. 정답과 근거, 필수 조건,
제품 일치, 반복 질문 탈출, 상담원 요청, 배송 조회의 주문·이메일·매장 일치 여부를
검사합니다. 새 모델이나 프롬프트는 별도 검증 대화와 비교한 뒤 적용합니다. 상세 운영
절차는 [AI 개선 운영 안내](ai_improvement_runbook.ko.md)와
[운영 서버 안내](production_runbook.md)를 참고합니다.
