# 고객 답변 품질 목표와 검증

목표는 고객이 질문한 내용에 정확하고 유용하게 답하는 것이다. 자동 검사 통과율을
고객 답변 품질의 100점으로 바꾸지 않는다. 검토한 대화의 평가와 운영 고객 전체의
성과도 구분한다.

## 답변 검토 기준

실제 모델 답변을 검토할 때 다음 배점을 사용한다. 현재 코드의 자동 검사 결과에서
이 점수를 산출하지 않으며, 모든 답변과 근거를 검토하기 전에는 미측정으로 남긴다.

| 기준 | 배점 | 만점의 조건 |
|---|---:|---|
| 사실과 출처 | 35 | 모델·가격·하중·문 폭·정책을 검증된 자료와 일치시키고 미확인 정보는 구분 |
| 문맥과 고객 조건 | 25 | 앞선 비교 대상, 정확한 예산·신체 조건, 정정·부정 표현을 유지 |
| 질문에 대한 답변 | 20 | 현재 질문에 먼저 답하고 불필요한 인터뷰·같은 질문 반복을 피함 |
| 안전과 실행 상태 | 10 | 위험 시 중단하고 의학적 한계·조회·발송·예약·취소 상태를 정확히 설명 |
| 언어와 다음 행동 | 10 | 지원 범위 안에서 고객이 이해할 언어로 설명하고 가능한 다음 행동 제시 |

위험을 놓친 재시험 안내, 확인된 모델 변경, 고객의 필수 조건을 위반한 추천,
실행하지 않은 취소·예약·발송 완료 주장, 다른 고객 정보 노출은 배포를 막는 결함이다.
다른 항목의 높은 점수로 상쇄하지 않는다.

## 실행 가능한 회귀 검사

`data/sales_customer_quality_cases.json`의 20개 대화·44턴은 실제 공개 Sales API와
서버에 저장한 상태로 검사한다. 비교 후속 질문, 모델 교체, 창고 재고의 근거,
기존 주문·반품·취소, 이메일 상태, 의료 효능·안전성, 스페인어 구매 조건을 포함한다.
개발에 사용한 검토된 회귀 사례이며 독립된 미공개 평가 자료가 아니다.

빈 상품 목록이 조건 검사만 통과하거나, 불명확한 메뉴가 질문에 답한 것으로 취급되지
않도록 긍정적인 답변 목표도 검사한다. 저장된 체중·예산·문 폭도 별도로 읽어 확인한다.
원래 실패 결과는 보존하고 후보에는 같은 사례와 기준을 적용한다.

```bash
pytest -q tests/test_sales_customer_quality_cases.py
python script/evaluate_llm_quality.py --dry-run --suite conversations \
  --cases data/sales_customer_quality_cases.json
```

평가 보고서의 `assertion_pass_rate_pct`는 명시한 검사의 통과율이다.
`answer_quality_score_100`은 사람의 답변 검토 없이 숫자로 채우지 않는다.
`turns_with_provider_evidence`는 실제 모델 실행 근거가 있는 응답 수이며 고객 해결률을
뜻하지 않는다. 기존 `pass_rate_pct`와 `quality_evaluated` 필드는 API 검사에 대한
호환 필드이므로 이 둘만으로 실제 모델 품질이 측정됐다고 해석하지 않는다.

## 실제 모델 평가와 운영 반영

별도 테스트 DB와 알림 발송을 막은 서버에서 기존 회귀 검사와 새 독립 사례를 함께
실행한다. 모델 ID·코드·카탈로그·사례 버전, 전체 실패와 미실행, 응답 지연을 기록한다.
일반 채팅의 모델 검증은 `--expected-model`과 인증된 실행 기록으로 확인한다.
서버에 설정한 모델 이름만으로 실제 호출 성공을 인정하지 않는다.

```bash
python script/evaluate_llm_quality.py --live \
  --base-url http://127.0.0.1:8000 \
  --expected-model '<configured-model-id>' \
  --out data/reports/answer-quality-candidate.json
```

실제 인증 값은 서버·실행 환경의 비밀 설정으로 주입한다. 운영 사이트를 테스트 서버로
간주해 전체 사례를 실행하지 않는다. 평가 API는 기록을 만들고 외부 알림을 실행할 수
있으므로 먼저 DB·알림 분리 상태를 확인한다.

사용자가 제공한 `help.osakichair.com`에는 읽기 전용 `/api/health` 조회를 시도했다.
현재 작업 환경의 프록시가 HTTPS CONNECT를 403으로 거절했다. 저장된 환경 설정
초안에는 이 호스트가 있지만 실행 환경의 허용 목록에는 적용되지 않은 상태였다.
이는 사이트 자체의 장애나 실제 답변 품질을 측정한 결과가 아니다.

실제 모델의 전체 답변 검토와 운영 반영은 이 접근 문제가 해소된 뒤 확인한다.
배포는 [운영 절차](production_runbook.md), 운영 성과는
[고객 성과 측정](measured_customer_success.ko.md)을 따른다.
